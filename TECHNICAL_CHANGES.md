# Технические изменения проекта

Дата: 2026-05-05

## Зависимости

### Python-зависимости

Файл `requirements.txt` не изменялся.

Новые Python-библиотеки не добавлялись. Проект продолжает использовать текущий стек:

- Django 6.0.4;
- PostgreSQL через `psycopg`;
- `python-dotenv`;
- `django-widget-tweaks`;
- стандартные Django apps.

### Frontend-зависимости

Новые frontend-пакеты не добавлялись.

Chart.js уже подключался в шаблоне статистики через CDN:

```html
<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
```

Я не добавлял npm, package.json, сборщик, Tailwind, React, Vue или другие frontend-инструменты.

### Dev-окружение

Для проверки проекта было создано локальное виртуальное окружение `.venv`.

Это не новая зависимость проекта, а локальный способ запуска проверок, потому что системный Python запрещает глобальную установку пакетов через pip.

Использованные команды проверки:

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py test mood ai_reports
```

Этот файл. Содержит техническое описание изменений, зависимостей и проверок.

### `ai_reports/services.py`

Новый сервис для генерации недельного отчета.

До изменения логика отчета находилась прямо во view `ai_reports/views.py`.

После изменения:

- `views.py` отвечает за HTTP-запрос и подготовку context;
- `services.py` отвечает за бизнес-логику анализа;
- код проще тестировать;
- позже можно подключить настоящий LLM или внешний AI-сервис без переписывания view.

Основные функции:

- `extract_keywords(notes)` - выделяет частые слова из заметок;
- `build_factor_insights(entries)` - ищет факторы, связанные с хорошими и сложными днями;
- `build_weekly_report(entries)` - собирает инсайты, средние значения и рекомендацию.

### `mood/migrations/0002_extend_mood_entry.py`

Новая миграция базы данных.

Добавляет в модель `MoodEntry` поля:

- `stress_score` - стресс по шкале 1-5;
- `anxiety_score` - тревожность по шкале 1-5;
- `sleep_hours` - количество часов сна;
- `factors` - факторы дня строкой через запятую;
- `gratitude` - короткая запись благодарности.

Также добавляет ограничение:

- один пользователь не может создать две записи на одну дату.

### `mood/migrations/0003_limit_note_and_edit_window.py`

Новая миграция для ограничения текста заметки.

Изменяет поле `note`:

- добавлен валидатор `MaxLengthValidator(400)`;
- в help text указано "До 400 символов".

Важно: ограничение редактирования 24 часа не требует отдельного поля в базе. Оно реализовано в Python-коде через `created_at`.

## Важное замечание

Текущий "AI"-отчет не является настоящим LLM/AI API. Это rule-based сервис инсайтов.

Так сделано сознательно:

- без новых зависимостей;
- без внешних API-ключей;
- без риска давать медицинские советы от имени модели;
- с возможностью позже заменить внутреннюю реализацию `build_weekly_report` на настоящий AI-сервис.
